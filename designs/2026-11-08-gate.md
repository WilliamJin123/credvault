# Key gate: processes hold stand-ins, the gate holds the keys (WA-1196)

## Goal

No agent, CLI or daemon holds a real API key. Each holds a stand-in (a sentinel). A local gate swaps the stand-in for the real key only on a request to that key's vendor hosts. A stolen stand-in is worthless off the gate. Each swap is one audited use.

Target state:

```
vault (SSM + Keychain-sealed file) ──► credvault gate (Node, holds real keys in memory)
                                            │ map over a pipe, never on disk
env files, llm keys file ──► sentinels      ▼
process ──HTTPS_PROXY──► mitmproxy (one listener per role) ──► smokescreen (role ACL, SSRF) ──► web
                           │ keyed vendor host: TLS ended, sentinel → real key, audit line
                           └ every other host: opaque tunnel, no CA needed
```

## What it fixes

- A prompt-injected agent passes a key to `weaver read <url>`: it holds only a sentinel, so the URL carries nothing.
- A beacon in a dependency reads the keys file: it gets sentinels.
- An agent reads a keys file that `denyRead` missed: same.
- Not fixed: misuse of a key on its own vendor (spend). Caps are a separate job.

## Engine options (spike results, 11-08)

| | How | For | Against |
|---|---|---|---|
| E1 | srt proxy-only mode + our decider | Anthropic's, TS, SSRF guard built in | Ends TLS on every host (all clients need the CA); `x-api-key` cannot be set (Anthropic, Exa use it); no upstream proxy, so it replaces smokescreen |
| E2 | mitmproxy (MIT, 12.x) in upstream mode to the role's smokescreen; `allow_hosts` = keyed vendor hosts; a small addon | Spike passed: real key on httpbin.org, other hosts opaque and work with no CA; any header, query or body; smokescreen keeps ACL, SSRF and the log | Python runtime and a Python addon; one more process |
| E3 | Base-URL gateway (Caddy `reverse_proxy` + `header_up`, or LiteLLM) | No CA | Every SDK needs a base URL; LLM-only for LiteLLM; misses OAuth tokens on site APIs |
| E4 | srt wraps each process (`credentials.mask`) | Generic swap in headers and body, SigV4 re-sign | Seatbelt cannot nest: fails for the relay and the desk |

**Pick E2.** Only a keyed host needs the CA, so a client without it fails on that host only.

## Where the code lives

Ranked priorities: one owner for a key's whole life (mint, store, project, use, audit) > reuse outside wren (the desk, a client's machine) > one policy file > little code.

| | Where | For | Against |
|---|---|---|---|
| L1 | credvault: `gate()` + a `credvault gate` bin + the addon file in the package; wren's Wrenfile names which keys each role may use; `wren egress apply` runs it under launchd | credvault already has keys, rings, vendor (`site`), `keyId`, the env projection and the hash-chained audit (`SecretUse` has `url`, `keyId`, `allowed`). "Every use audited" becomes true by construction. Any app can run it | credvault grows a process and a Python file; the vault's store config is given twice (autobrowse and the gate config) |
| L2 | wren `packages/egress` | All network policy in one package | wren must read the operator vault, which autobrowse owns; key logic splits across repos; not reusable |
| L3 | autobrowse `creds gate` | Reuses its store wiring | autobrowse is the browser app; the gate serves every role |

**Pick L1.** Split: credvault = keys, sentinels, swap, audit. wren egress = roles, hosts, ports, launchd. autobrowse `creds key project --mask` writes sentinels into env files.

## Shape (L1 + E2)

- **Sentinel**: `wsk_` + base32 of HMAC-SHA256(gate key, address), 32 characters. The gate key is in the Keychain. Stable across restarts, so files never change when the gate restarts. A rotated key keeps its address, so its sentinel stays.
- **Vendor hosts**: a catalog in credvault (`anthropic` → `api.anthropic.com`, `exa` → `api.exa.ai`, …). A key may add `hosts`.
- **`credvault gate --config <file>`**: reads the keys a role may use, builds sentinel → (real, hosts) in memory, starts `mitmdump` with one listener per role (upstream = the role's smokescreen, `allow_hosts` = the union of its keys' hosts), hands the map to the addon over a pipe. The addon swaps a sentinel in a header or the query on a matching host. A sentinel on a host outside its key's list: 403 and a canary alert. Each swap: one line back on a pipe; the gate writes the `SecretUse` (vendor, endpoint without query, `keyId`, role).
- **CA**: made by mitmproxy in `~/.config/wren/egress/gate/` (0600). The key path joins Wrenfile `secrets`. Clients get `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`/`REQUESTS_CA_BUNDLE` (system roots + the CA).
- **Wrenfile**: `roles.<name>.keys: [address or vendor]`. `proxyEnv` points at the gate's port for that role.
- **Projection**: `projectKeys(keys, { mask })` writes sentinels in place of values. autobrowse `creds key project --mask` writes the desk's env. The model keys file at the workspace root gets the same.
- **Ephemeral keys** (a client's own key for one chat): `gate.register(value, hosts, ttl)` over a 0600 Unix socket returns a sentinel. The relay calls it before launch.

## Order

1. credvault: sentinel, vendor catalog, `gate()`, addon, bin, tests. Version bump.
2. wren egress: `keys` per role, apply runs the gate, env points at it.
3. weaver role first (model keys, Exa). Then the desk. Then a client's own key in the relay.
4. After each: the real-key files hold sentinels; read the audit; the old raw values leave disk.
